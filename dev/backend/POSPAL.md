# 银豹收银系统接入与联调

## 2026-11-20 购买前再次核验

普通商品现金购物、积分加现金补差，在创建订单、创建或复用待支付单、发起 LFWin 付款前，服务端重新检查有效会员及可信手机号，再调用 `/openapi/v3/customer/increment-page` 按绑定卡号实时回查。只在唯一会员的 UID、卡号、手机号、启用/挂失状态及北京时间到期时间与本地最新权益完全一致时放行，不凭后台历史“已同步”标记放行。查询期间会员期限、手机号或关联变化时拒绝，刷新后重试；本地有效注册赠送会员同样可购买，不限制角色标签。

缺少微信手机号授权、尚未完成银豹关联、身份冲突或期限未同步给出明确提醒；接口未配置、额度暂停/4021、网络失败时暂停新的购买及付款，提示联系管理员或稍后重试。校验仅查询，不在购买请求里创建会员或改银豹资料。新订单拒绝时不扣库存、积分，不创建订单或支付单；已有待支付订单核验失败时保持原样，仍可取消。异步支付通知照常对账，不因事后会员状态改变拒绝已发生的付款。相同幂等键找回已存在订单仍返回原单，继续付款须重新核验。

纯积分兑换及“买商品送会员”纯专区现金订单保留原有非会员规则；专区免会员资格由服务端商品校验生成并保存 `membershipRequired=false` 快照，不能通过请求字段自行豁免，混入普通商品必须按普通会员购买校验。小程序结算页持续显示校验失败提醒，现有客户端也会收到接口错误提示。

后台“用户/会员管理”已增加“银豹同步”列，显示每位用户的任务状态、成功时回查确认的到期时间和最近成功时间、失败原因/下次重试及额度暂停时间。没有任务显示“未入队”；已排队不等于成功。拥有 `customer:read` 可查看摘要，`integration:write` 可对失败/跳过任务点击“重新同步”。状态通过 `/api/admin/users` 的 `pospalMembershipSync` 返回，所有用户均覆盖，不依赖状态接口最近 50 条。该摘要不暴露门店账号、银豹 UID、卡号或凭据；点击顶部刷新可更新。

## 2026-11-20 注册赠送会员纳入同步

注册赠送的体验会员与积分开通、商品赠送会员使用相同同步规则：以有效 `memberUntil` 为准，不要求 `role=member`。微信注册已完成手机号授权时，保存用户资料时同时保存同步任务；已有赠送会员授权/登录时补建缺失任务。重复登录保留同一期限任务的成功回执和失败退避，不重复建档，也不延长本地或银豹期限。

后端启动时自动补齐所有有效且未停用会员的缺失或过时任务，包括历史注册赠送会员。未授权手机号的用户以 `waiting_phone` 入队，授权后恢复；已有同一期限的成功、处理中、重试任务保持不变。该规则从本次更新起替代下文“不自动迁移存量会员”的历史约定。

银豹返回 4021 时持久化账号级一小时暂停时间 `membershipSyncQuotaUntil`，当前失败任务保留为 retry，其他任务保留队列，避免逐个重复消耗额度。重启、注册、重新授权均不绕过暂停；到时自动重试。管理状态 `membershipSync.quotaRetryAt` 返回该时间。同步成功仍须查询确认会员身份及期限一致。

## 2026-11-19 会员开通、续费及期限同步

积分开通/续费、买商品送会员支付成功时，随本地权益保存生成 `config.pospalIntegration.membershipSyncJobs[userId]` 任务。后台调整会员期限、退款回收尚未使用的赠送时长也生成任务。每个用户仅保留最新目标，重复支付通知不重复延长；2026-11-20 起注册赠送及存量会员也按上节规则纳入同步。已移除的会员码页面不是自动同步前置条件。

后端启动后及每 10 秒扫描一次，单批最多处理 10 个到期任务。首次使用微信授权验证的手机号查询银豹：唯一有效会员直接关联；不存在时按持久化固定卡号建档，并传姓名/昵称、手机号、到期时间。已存在的门店会员保留门店姓名、手机号和卡号，更新 `customerExt.nickName` 及期限。历史用户缺少可信手机号时显示 `waiting_phone`，授权绑定后自动恢复。手机号重复、停用/挂失、查询不完整、身份冲突或门店切换均阻止外部写入，需先核对资料。

接口均为 JSON POST，基础域名由 `POSPAL_BASE_URL` 指定，默认 `https://platform.pospal.cn`：

- `/openapi/v3/customer/increment-page`：按卡号或手机号查询/确认。
- `/openapi/v3/customer/add`：会员不存在时新增；`number`、`tel` 必填，`validateTelUnique: true`，`expiryDate` 为本地到期时间。
- `/openapi/v3/customer/update`：按原卡号定位，`updateMask: ["expiryDate", "customerExt.nickName"]`（没有昵称时只传期限），同步最新绝对期限。

`expiryDate` 使用北京时间 `yyyy-MM-dd HH:mm:ss`，以本地 `memberUntil` 为唯一期限来源，与执行服务器时区无关。未到期的续费延续本地原期限，已到期的续费从当前时间起算，沿用本地现有 30 天/月及商品快照天数规则。清除会员时传已到期的有限时间，不能清空字段，否则银豹可能变成无期限会员。不会更改银豹积分、余额、折扣等级，不会将银豹期限反向覆盖本地。

发送前保存任务意图，查询校验身份后更新，再查询确认 `expiryDate` 相同才标记 `synced`。超时或失败保存为 `retry`，30 秒起指数退避至最长一小时；未确认任务重启后继续处理。更新使用绝对期限，超时重试不会再增加一段时长；固定卡号避免建档响应丢失后重复创建。更新期间发生续费时保留新任务，继续推送最新期限。存储保存失败暂停 worker，修复存储并重启后恢复。外部失败不影响已确认的本地支付权益。

管理接口：

- `GET /api/admin/integrations/pospal/status`（`integration:read`）：返回 `membershipSync.counts` 与最近 50 个用户任务，含状态、目标期限、重试时间、最近错误及最近成功时间。
- `POST /api/admin/integrations/pospal/members/{userId}/sync`（`integration:write`）：将该用户最新本地期限重新排队，返回 202 表示任务已保存，不代表银豹已成功。可用于修复配置后重试或核对后补同步存量会员。

本流程不依赖银豹异步回调；原 `/api/pospal/callback` 的 Token 鉴权与官方签名适配问题仍需另行处理。

2026-11-19 已在线读取官方会员文档核对 `expiryDate`、`updateMask` 和日期格式。自动建档、续费、超时、重启及并发恢复使用模拟银豹客户端验证，尚未写入真实银豹会员数据；部署前需确认运行环境凭据、银豹额度可用，并完成真实会员的开通、续费及门店到期验收。此前 2026-11-16 的只读查询返回 4021，不能据此判断今天的额度状态。

验证：`node --test test/unit/pospal-membership-sync.test.js test/unit/member-provision.test.js test/unit/member-payment-recovery.test.js test/unit/product-membership-gift.test.js test/unit/membership-adjustment.test.js test/unit/phone-binding.test.js`。

## 小程序门店会员码

入口：小程序「我的 → 会员码」。`GET /api/me/member-code` 仅向登录本人返回已同步的银豹 `number`（Code 128），保留前导零。GET 不产生外部写入；POST 自动建档/关联，均不扣款、不调整两端会员等级、积分或余额。

已开通会员首次进入会员码页，点击「授权手机号，获取会员码」。小程序将微信 `getPhoneNumber` 的一次性 code 提交至 `POST /api/me/member-code`，后端通过微信官方接口取得并校验手机号及 appid，不信任客户端手填号码。已有唯一启用的银豹会员按手机号关联；没有则用固定卡号建档，查询确认后持久化身份映射再展示条码。微信登录本身不包含手机号，因此需要这一次用户授权；后续打开页面自动恢复未完成流程。支付回调不等待外部建档，自动建档触发点为会员首次出示会员码。

2026-11-16 核对官方文档：https://platform.pospal.cn/openapi-doc/customer.html#customer-add 。V3 `/customer/add` 的 `number` 和 `tel` 均必填；`number` 在连锁内唯一，`validateTelUnique: true` 启用手机号查重。查询使用 `/customer/increment-page` 的 `number` 或 `tel` 筛选，完整且唯一才关联。手机号目前限定微信授权返回的中国大陆号码。

建档前将手机号授权结果、门店账号、固定卡号和归属标记持久化到 `config.pospalIntegration.memberProvisions`，不保存微信 code/access_token。每次重试先查回原卡号与手机号，不换卡号；超时后即使银豹已建档也能恢复。查询不完整、重复会员、停用会员、卡号冲突、其他用户已关联、门店账号变化均阻止自动绑定。服务端同账号请求合并；PG 状态 CAS 写入成功后才调用新增接口。失败后等待 30 秒再重试，未完成状态跨重启保留。

上线要求：后端配置 `WECHAT_APPID/WECHAT_APPSECRET` 和 `POSPAL_APP_ID/APP_KEY/ACCOUNT`；微信小程序已具备手机号快速验证能力，并在隐私保护指引中说明用于门店会员建档/关联和向银豹提供手机号。微信和银豹调用额度需可用。首次授权必须在微信真机完成，不用虚构号码在生产建档。银豹默认会员等级为 0；当前会员到期同步以本文 2026-11-19 流程为准，折扣等级不在此流程内。

2026-11-16 线上只读验证：使用部署环境凭据按固定测试卡号查询，银豹返回 `4021`（Token 额度不足）。未创建任何测试会员；需充值银豹额度并由真实用户在更新后的小程序中授权手机号，再完成门店验收。

纯激光扫码枪可能无法读取手机屏幕，需要使用支持屏幕识读及 Code 128 的扫描器；也可以手动输入显示的卡号。

门店验收：收银员先聚焦会员识别输入框，扫描小程序条形码，确认返回的是同一会员；测试含前导零的卡号、普通卡号、无关联账号和退回页面后重新进入。建议关闭扫码枪自动添加的前缀，按收银软件需要设置回车后缀。扫码只识别会员，不代表付款授权。

## 复测

在 `dev/backend` 执行：

```sh
npm run pospal:check
node --test test/unit/pospal-integration.test.js
```

联调脚本加载与后端相同的环境配置，依次查询商品、门店、库存、会员、销售单、网单、支付方式；每个接口只请求一页，仅输出条数和状态。遇到余额不足或网络故障停止后续请求，失败退出码为 1。不会向银豹写入订单、库存、积分或余额。接口调用按银豹规则消耗 Token。

后台现有接口（需管理员登录及 integration 权限）：

- `GET /api/admin/integrations/pospal/status`：配置和最近同步结果。
- `POST /api/admin/integrations/pospal/sync`：同步商品、库存、会员、销售单、网单。
- `POST /api/admin/integrations/pospal/orders/{orderId}/push`：推送已支付现金订单，要求商品条码映射。

首次商品同步可用 `{"resources":["products"],"maxPages":1,"limit":10,"autoCreate":true,"resetCursor":true}`。导入商品默认为下架，需审核后发布。同步会更新本地映射及游标；库存同步默认覆盖本地库存，需预览时传 `apply:false`。会员同步只建立关联，不导入银豹余额或积分。
