# 芯烨云小票打印接入

默认使用 80mm 小票机（每行 48 个英文字符或 24 个汉字），设备设置可切换 58mm（32 / 16）。设备必须支持芯烨云；仅带 USB 接口、未接入芯烨云的普通小票机不能直接使用本接口。本功能打印商城商品订单，与银豹线下收银打印机独立配置。

## 首次配置

1. 在芯烨云开通开发者账号，取得用户名称、UserKEY，确认设备 SN/PID 及归属。
2. 在服务器环境变量或后端忽略提交的 `.env` 中设置以下配置；不要将密钥写入前端、Git 或公开文档：

   ```dotenv
   XPYUN_USER=芯烨云开发者用户名称
   XPYUN_USER_KEY=芯烨云UserKEY
   XPYUN_ENABLED=0
   ```

3. 重启后端，进入 `/admin` → **打印管理**，新增设备。默认纸宽 80mm，选择“自提订单 + 所属自提点”或“配送订单”，配置份数（1–5）、店名、底部文案、启用开关和自动打印开关。设备 SN 不可修改，换机需停用旧设备并新增。
4. 点击“注册设备”，再检查设备在线状态。已绑定在同一芯烨云账号下的设备可直接“检查状态”验证；离线也能验证归属，但不能立即出纸。
5. 将 `XPYUN_ENABLED=1` 并重启，点击“打印测试页”，稍后“刷新状态”。确认纸张和中文排版清晰，任务从“待发送”→“云端排队”→“已打印”。
6. 完成一笔商品订单支付，确认对应设备自动出单、订单号二维码清晰。打印开关仅对之后新支付订单生成自动任务，历史订单可在订单管理点击“打印小票”。

缺少云账号配置时不会调用打印平台。发送开关关闭时保留本地任务，重新开启后会发送仍符合条件的积压任务；开启前请在后台核对并取消不再需要的任务。

权限：查看入口和列表需 `order:read`；设备配置、注册、设备查询和测试页需 `config:write`；订单打印、补打和任务处理需 `order:fulfillment`。超级管理员具备全部权限。给运营人员配置打印机时，同时授予 `order:read` 与 `config:write`。

## 订单与打印规则

- 现金、积分加现金订单在支付成功入账时入队；纯积分订单提交扣分成功时入队。会员开通支付不打印商品小票。
- 自提按自提点分配打印机，配送发给启用的配送打印机；配置多台匹配设备会各打一份任务，每台再按“份数”出纸。
- 自动任务以订单与设备去重；手动请求使用幂等键。已有排队或结果待核对的任务时阻止重复提交；已打印订单补打必须确认并填写原因，小票标注“补打联”。
- 小票包含订单号、商品及数量、现金与积分合计、自提点或配送地址/时段、已配置商品库位；手动打印时也会带上已有的站点储位和袋数。支付时生成的自动小票使用当时的数据快照，不会因后续收货更新原小票。
- 二维码仅含商城订单号，用于识别订单；不包含用户提货核销码，也不会代替小程序提货核验。
- 模拟支付、测试跳过支付及缺少真实支付证据的现金订单显著标注“测试订单，未实际收款”。测试页不会修改订单、金额、库存或会员。
- 发送前若订单已取消、退款中、已退款，或设备站点不再匹配，取消本地任务。已发给云端的任务无法靠商城停用设备或取消订单撤回，需在芯烨云后台清理并核对纸张。

## 异常处理

| 状态 | 含义与操作 |
| --- | --- |
| 待发送 | 等待后台发送；确认服务开启、设备启用且已注册/验证。可以取消。 |
| 发送中 | 发送意图已保存。服务中断后恢复为“发送结果待核对”。 |
| 云端排队 | 芯烨云接受请求并返回任务号，尚未确认出纸。使用“查询出纸”，不要另建补打任务。 |
| 已打印 | 平台查询返回已打印，或管理员核实实际出纸后确认。 |
| 发送失败 | 平台明确拒绝，或小票超长。修复原因后重试；超长小票没有内容快照，需拆分处理，不可原任务重试。 |
| 发送结果待核对 | 超时、网络异常、返回缺少任务号或服务中断。禁止自动重发，先查芯烨云任务及纸张。 |
| 出纸结果待核对 | 超过 24 小时仍未确认。支持平台查询或人工核对。 |
| 已取消 | 本地未发送任务已取消，或人工确认云端已清除。重新打印前仍需核实旧任务。 |

人工核对需要填写原因：“已打印”表示确认出纸；“已清除”表示确认未出纸且云端无待打印任务。不能仅因打印机离线就确认已清除，否则联网后可能重复出纸。平台返回的 `attached` 仅用于关联查询，不作为平台幂等保证。

商品小票的云端排队有效期为 3600 秒，测试页 300 秒。轮询每 10 秒处理最多 10 条任务，轮转避免长队列饿死；不依赖回调。`queryOrderState=false` 不代表发送失败，不会触发自动重发。

打印前持久化发送意图，持久化失败会暂停该实例的打印服务并在管理页提示。修复存储、重启后对“待核对”任务逐条核查。当前项目是整份状态持久化架构，使用单个应用写入实例；不能部署多个共享 JSON/SQLite 文件的进程，也不能把本模块当作分布式任务锁使用。

设备、任务和审计记录使用项目现有 JSON / SQLite / PostgreSQL 存储。SQLite 自动执行 `014_print_state.sql`。打印内容含订单收货信息，应按订单数据保护备份和磁盘权限；管理列表不返回小票正文和内部幂等键。任务记录当前不自动清理，需结合业务量规划归档。

## 接口与验收

完整请求定义见 `openapi.yaml`。所有接口需管理员 Bearer Token：

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/printing` | 设备、最近 200 条任务及服务状态 |
| `POST /api/admin/printing/printers` | 新增设备 |
| `PATCH /api/admin/printing/printers/{id}` | 配置或停用设备 |
| `POST /api/admin/printing/printers/{id}/{action}` | `register` / `status` / `test` |
| `POST /api/admin/printing/orders/{orderId}` | 手动打印与补打 |
| `POST /api/admin/printing/jobs/{id}/{action}` | `query` / `retry` / `cancel` / `resolve` |

本地验证：`npm run test:unit`、`npm run db:check`、`npm run api:check`；打印专项为 `node --no-warnings --test test/unit/printing.test.js`。自动测试使用模拟云接口，覆盖签名、回调入队、重复请求、权限、退款拦截、断网、服务中断、保存失败和 SQLite 重载。

实机验收还需：账号与设备验证 → 80mm 测试页 → 现金/纯积分各一单 → 多自提点分流 → 同一订单重复支付通知不重印 → 离线后恢复联网 → 断网待核对 → 已打印订单补打 → 退款订单不再发送。当前没有真实账号和设备，尚未完成实机出纸验收。
