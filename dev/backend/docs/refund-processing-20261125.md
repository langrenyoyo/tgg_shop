# 2026-11-25 二级审核后退款状态修复

线上近期现金退款在二级审核成功后显示“退款发起结果未知”，随后通过已验签的回调完成退款，但原异常未自动关闭。只读核对确认这些退款各有一条退款现金流水，未重复入账。

LFWin 官方 v4 协议规定：退款发起响应 `status=4001` 表示处理中，可能没有签名；`10000` 也只代表请求成功，需继续查询退款最终结果。原通用客户端只接受 `10000`，导致正常受理被当作异常。

退款查询返回带 `lists` 的响应。线上只读请求验证：嵌套列表需要按 PHP JSON 格式（Unicode 转义）参与签名，原代码将对象转为普通字符串导致验签失败；查询结果也未选择对应列表行。

修复后：

- 仅退款接口接受 `4001` 为受理提示。有签名时仍须验签，提示本身绝不用于退款入账。`10000` 发起结果同样只进入处理中。
- 查询完整验签，保留所有列表字段；要求唯一匹配商户退款号、原平台支付订单号和已知退款流水号。成功前校验退款金额；`refund_status=0/1/2` 分别为处理中/成功/失败。
- 后台每 30 秒检查一轮，距离上次请求至少 60 秒才查询，每轮最多 3 单。只查结果，不自动重新发起退款。后台退款列表增加“查询退款结果”按钮。
- 同一退款单的发起/查询互斥；回调先成功时，稍后返回的发起/查询结果不得覆盖成功状态。重复成功结果不再重复状态历史或账务。
- 成功后关闭对应“发起结果未知”异常及关联工单；启动时仅用既有退款成功状态和现金流水清理历史遗留异常，不重新退款或修改金额。
