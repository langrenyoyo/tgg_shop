# 2026-11-26 广告与积分签到

对应《小程序广告配置20261126.docx》，四种广告位从 `server.txt` 录入服务器后台签到配置，不将服务器凭据提交 Git。

位置：

- 首页：横幅、自提站、公告、搜索依次排列。
- 赚积分：横幅替换原顶部标题文案。
- 签到：横幅替换欢迎语，底部横幅及信息流；页上广告不参与完成轮数。
- 分类：横幅替换“发现新鲜好物”；全部分类的商品滚动区顶部另置横幅，随商品滚动，不置顶。
- 企业客服、会员页底部：信息流；邀请页“邀请有礼”上方：横幅。

使用原生 `ad` / `ad-custom`，按后台广告 ID 加载，失败时折叠容器并保留组件以接收后续加载回调。全局组件合并并短时缓存公开配置请求。

签到流程：进入页面先开始当日会话及一轮插屏，完成后等待用户点击“立即签到”播放激励视频和后置插屏。完整一组才计一轮，后台决定固定随机轮数和奖励。默认 20 秒轮间倒计时结束准备下一轮前置插屏；达到轮数点击完成签到后一次入账。刷新不重抽轮数，中断未完成组重来，完成组保留。

服务端开启 `SIGNIN_AD_VERIFICATION_MODE=wechat_client` 使用微信 SDK `onClose`/`isEnded` 完成报告。`/api/coin-signin/begin` 先签发与用户、当天、会话、步骤绑定的随机令牌，后续 `/step` 核对顺序、令牌、最短经过时间及视频完整观看标记。旧的外部验证适配器保留。

**边界：微信 SDK 回调来自客户端，不是微信广告平台签名验证，服务端令牌与时间检查无法证明客户端报告没有被篡改。** 如后续具备可独立验证的广告凭据服务，应切回外部验证模式。不会将插屏点击、横幅展示或收入分润作为完成条件，不会生成模拟观看。

后台新配置 `rewardAsset=points`，完整完成后更新用户积分余额、积分流水与签到记录，用户/北京时间日幂等，存储失败回滚，无邀请分润，不改变可提现余额。旧会话和独立金币记录保留其原奖励类型。字段 `rewardCoins`、`balanceCoins` 为兼容旧接口继续保留；积分模式同时返回 `unit=积分` 和 `balancePoints`。

真机验证需上传新版小程序，确认流量主广告已审核启用。开发者工具或无广告填充时不能认定真实广告展示、观看和平台收入成功。先用本地隔离状态验证奖励及幂等，正式账号不代刷广告或生成测试奖励。
