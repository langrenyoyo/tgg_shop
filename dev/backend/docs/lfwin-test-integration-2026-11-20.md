## 本次修复

- 未支付订单查单响应的空字符串字段，例如 `trade_no`、`buyer_account`、`fund_bill_list`，必须按原样参与验签。原代码剔除空字段，会拒绝有效响应。修复保留空字段；删除或篡改字段仍验签失败。
- 按官方文档使用微信二维码 `wxpay.comm.qrcode` 和小程序 `heli.mini.pay`，替换原有未列入文档的默认服务码。可通过服务端 `LFWIN_QRCODE_SERVICE`、`LFWIN_MINI_SERVICE` 配置实际通道。
- 仅按商户订单号查单时必须传 `order_time` 定位月份；现有项目支付服务已传 `payment.createdAt`，直接联调脚本也已补齐。

## 限制及后续联调

官方“线上支付对接须知”要求线上接口使用 `https://api2.lfwin.com`，即使使用测试凭据；UAT 域名不支持线上支付。不能仅按域名是否带 `uat` 判断凭据性质。MD5 为官方测试资料确认的签名方式；正式收款仍需正式商户凭据和通道确认。

当前小程序需支付服务商为当前 `WECHAT_APPID` 完成商户报备及绑定，并确认使用的 `service`。不能以示例 AppID/OpenID 替换真实用户身份，也不能由示例预支付成功推断当前小程序能付款。

测试网关按官方说明不发送异步通知；本次没有支付成功、真实回调或退款成功的证据。报备完成后，需要用户在小程序完成测试付款，再验证查询/回调、入账、赠会员及退款。银豹会员核验的手机号和额度要求依旧适用，本次未绕过它。

测试凭据仅用于独立脚本/内存流程，没有替换主服务收款凭据或将支付开关改为模拟成功。
