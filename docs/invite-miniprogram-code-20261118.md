# 小程序码邀请（2026-11-18）

## 用户流程

1. 登录后进入“邀请有礼”，点击“生成专属小程序码”。
2. 预览或保存到相册，用户自行发送好友或打印。保存权限被拒绝时可打开设置后重试。
3. 好友使用微信扫码进入首页，邀请码通过 `query.scene` 自动保存。登录页显示邀请码，可更正或清除。
4. 新用户完成手机号授权注册后绑定邀请关系，并按后台配置发放一次注册奖励。已有账号不重新绑定、不重复发奖。邀请码按注册前最后收到或手动填写的值生效。

## 接口与配置

- `GET /api/invite/code` 需要用户登录，仅生成当前账号自己的邀请小程序码，忽略客户端指定的用户、scene、页面和版本。返回 `userId/inviteCode/page/envVersion/mimeType/imageBase64`，HTTP `Cache-Control: no-store`。
- 服务器调用微信 `cgi-bin/stable_token` 与 `wxa/getwxacodeunlimit`。AppSecret 和 access_token 不发给客户端；图像为 PNG/JPEG，最大 1 MiB。
- 复用 `WECHAT_APPID`、`WECHAT_APPSECRET`。可选 `WECHAT_INVITE_CODE_ENV=release`，仅允许 `release/trial/develop`，生产默认正式版。服务端微信网络访问及 IP 白名单要求与现有登录服务一致。
- 固定页面 `pages/home/index`，`check_path=true`。应先发布包含本次 scene 解析的新版本；旧版虽可能成功生成图片，但无法保证扫码邀请绑定。体验版联调需在独立测试后端配置 `trial` 并上传对应体验版，不能仅改变客户端环境。
- 服务进程缓存 token；图片缓存 24 小时、最多 64 项，同码并发合并、在途上限 32。每个客户端地址每分钟最多请求 10 次。缓存过期或进程重启仅影响再次生成，不使已保存的邀请图片失效；实际绑定仍校验邀请人有效状态。
- 微信 token 过期仅重试一次；页面未发布、额度不足、网络失败或图片格式异常提供可重试错误，不转发微信原始敏感响应。
- 客户端将 base64 写入本地图片后展示；退出页面或更换账号清理文件，异步响应校验账号，防止展示、保存上一账号的码。

## 验证与发布

- `test/unit/invite-code.test.js`：微信接口合同、缓存并发、token 刷新、错误恢复、环境限制、限流、图片保存权限、账号切换、页面销毁及文件写入失败。
- `test/unit/invite-flow-closure.test.js`：实际 API 鉴权和注册链路、scene 冷热启动解析、注册奖励幂等、无效码清除恢复、手动输入、原有任务提成审计问题复现。
- 本地使用微信开发者工具自带编译器编译 WXML/WXSS 与脚本；运行后端完整 `npm test`。
- 验证结果：674 项单元/审计检查通过（包含 1 项原有审计问题的复现），JSON/SQLite/PostgreSQL 三种存储冒烟通过，5 项端到端测试通过；22 个页面、22 个模板和 19 个样式表编译通过。全量日志：`.codex-tmp/invite-code-full-test-20261118.log`。
- 服务器更新后需在微信开发者工具上传小程序、提交审核并发布。真机验收用邀请人 A 生成码、新用户 B 扫码注册，核对 A 的邀请列表和奖励流水；再用 B 扫另一人的码，确认不会重复绑定或发奖。
- 自动化中的微信登录、手机号及二维码响应为模拟，不能代表真实账号的扫码、授权或相册权限已经验收。此次不在生产创建用户或发放测试积分。

## 已知独立问题

后台邀请审计的任务提成统计仍存在提交单 ID 归属错误；原有 `shareUrl` 仍是示例网页地址。本功能使用官方小程序码和原有小程序分享路径，不使用该网页链接。详见 `invite-flow-test-20261118.md`。
